# 用户工作流

本插件保存由运维人员维护的工作流定义，用于把已接入的插件工具、上传节点、配置提取节点和依赖关系组合成可重复执行的流程。

## 功能

- 提供用户自定义工作流清单。
- 支持工作流运行参数、节点参数映射、上传文件引用和配置文件提取。
- 当前包含示例测试流程和部署包上传校验流程。

## 输入

- 工作流参数：由各 `workflows/*.yaml` 文件中的 `parameters` 定义。
- 节点参数：由工作流节点引用的插件工具定义。
- 上传文件：上传节点运行时接收本地文件或目录，供后续节点通过 `{{ .steps.<node>.file.* }}` 引用。

## 输出

- 运行记录写入平台运行日志目录。
- 工具标准输出和错误输出会进入对应步骤日志。
- 配置提取节点可把上传或工具输出定位到的文件保存为工作流配置文件。

## 风险

- 工作流可能调用高风险工具；执行前应确认目标环境、参数和工具自身确认策略。
- 上传文件和配置文件可能包含敏感信息，避免在参数、stdout 或 stderr 中输出密钥。
- 配置提取节点开启覆盖时会替换同名配置文件，执行前应确认目标路径。

## 回滚

- 工作流定义异常时，可恢复 `workflows/*.yaml` 的上一个版本。
- 配置文件误改时，可从备份或上一份运行产物恢复。
- 工具执行失败时，优先查看运行记录、步骤日志和支持包，再按目标系统的回滚流程处理。

## 维护

- 维护人：运维平台维护人员。
- 变更工作流后运行 `./bin/opsctl.exe validate`，确认工具、工作流和配置引用仍然有效。
